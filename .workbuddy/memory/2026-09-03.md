# 2026-09-03

## 完成：Dispense 配置下发器 - 健壮性 + 命名 + 性能收尾

基于已落地的零依赖架构（Application→currentFile→File→实体，索引派生、流式下发），本轮新增/修正：

1. **项目命名**：`package.json` name 由 `json-manager` 改为 **`dispense`**（开源名，直译「下发」）；
   README 标题改为 `Dispense · 配置下发器`；server 启动横幅加 Dispense 前缀；补充 keywords。

2. **下发端点健壮性（用户硬性要求）**：`routes/delivery.js`
   - 未知 token / 未设当前文件 / 实体缺失 / 任意异常 → 一律返回 `200 + 空 body + text/plain`，不报错不崩。
   - `lib/mime.js`：无扩展名（或未知后缀）默认 `text/plain`（原 `application/octet-stream`），
     满足「无文件后缀 = 纯文本」约定；`Content-Type` 按下发名后缀，`/d/:token` 响应头类型正确。

3. **存储性能优化**：`lib/fsx.js` 的 `writeFileAtomic` 增加 `sync` 选项；`appStore.writeIndex` 改用
   `sync:false`（索引由 app.json 派生、启动重建自愈，无需 fsync），批量写入提速数倍；
   真相来源 app.json 与实体仍 fsync。

4. **测试补齐**：新增 `test/delivery.test.js`（Content-Type 按后缀、无后缀兜底、未知/缺文件/坏文件
   空响应、60 并发未知链接压测、?dl=1 附件）、`test/performance.test.js`（4000 文件规模：重建索引
   <1s、下发 median <20ms、索引 164KB）。更新 `test/api.test.js` 两处「404」断言改为空 200。

**结果**：`node --test test/*.test.js` 全部通过（75 用例）。运行时 SLA 达标（O(1) 索引定位 + 流式）。
沙箱 fsync 慢（≈3 文件/秒）属环境限制，不影响产品运行时性能。
