## 完成：GitHub Actions 部署可行性评估 + 自动部署预案
用户问「能否以 Action 方式部署在 GitHub 上、让它跑着、push 时更新重启」。

**结论：不能把服务本体跑在 GitHub Actions 上**（托管 Runner 是临时 VM：job ≤6h、磁盘用后即焚、
无公网入站；与 Dispense 本地文件型存储 + 7×24 在线 + /d/:token 对外访问三重冲突）。
Actions 只能当「push 自动部署扳机」，宿主必须有公网服务器。用户当前**暂无服务器**。

**产出（等有服务器即可启用）：**
- `.github/workflows/deploy.yml`（新增）：push main → SSH（appleboy/ssh-action）→ git pull
  --ff-only → npm test → pm2 reload dispense。secrets 未配时 job 自动跳过，不影响 push 绿灯。
  需 secrets：DEPLOY_HOST / DEPLOY_USER / DEPLOY_SSH_KEY / DEPLOY_PATH（DEPLOY_PORT 可选）。
- `docs/DEPLOY.md`（新增）：为什么不能纯 Actions 跑 + 架构图 + 服务器一次性初始化 + secrets 配置 +
  验证/回滚 + 选服务器建议（国内轻量云推荐；海外 PaaS 免费层无持久卷/会休眠，不适用本地文件型存储）。
- `ecosystem.config.js`：PM2 进程名 `json-manager` → **`dispense`**（未部署过，零副作用，对齐仓库名）。

**验证**：`node --test test/*.test.js` 75/75 通过；deploy.yml YAML 校验 OK。
